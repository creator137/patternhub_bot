# Политика новинок и бесплатного раздела

Решение клиентки от 28.10.2026: включать позиции за 1 ₽ в бесплатный раздел;
новинки определять по публикации у производителей за последние 30–60 дней.
Принято окно 60 дней (`NEW_WINDOW_DAYS` в `app/models/catalog_policy.py`).
Пользователь отдельно подтвердил строгое правило по датам: метки NEW без даты
не используются даже как временная замена.

## Новинки

Общее поле `source_published_at` в ParsedProduct/Product/SQLite — дата публикации
производителем, UTC. Данные проходят общий repository и CatalogService.
`is_new` после нормализации и при чтении: дата находится между now−60 days и now.
Это проверяется общей SQL-политикой в фильтрах, counts, stats и общей Python-политикой
при чтении товара. Поэтому товар выходит из новинок даже при сбое очередного импорта.
Будущие, неизвестные и невалидные даты не попадают в этот раздел.

Старая отметка производителя сохраняется отдельно в `source_new_badge`. SQLite
миграция копирует туда прежний `is_new`, не придумывая даты. Сам `is_new` в SQLite
поддерживается как вычисляемый кэш; authoritative selection использует дату при
каждом запросе, а не устаревший кэш. Listing без даты сохраняет ранее известную.
Обновление `updated_at`, первый импорт и изменение фото не продлевают новизну.

Studio Yusupova: публичный `/wp-json/wp/v2/product`, поля `id,date_gmt`, до 100
позиций на страницу. ID совпадают с Woo Store API. Это дополнительные массовые
запросы существующего provider, без обхода каждой карточки. `date_gmt` означает
публикацию, `modified_gmt` намеренно игнорируется.
[Описание семантики полей WordPress](https://developer.wordpress.org/rest-api/reference/posts/).
Robots не запрещает этот endpoint. Ошибка получения дат не запускает деактивацию
товаров; уже полученные даты сохраняются.

Общий detail enrichment принимает `datePublished` только собственного Product
JSON-LD либо `product:published_time` на product page. Даты отзывов, рекомендаций,
статей, `dateModified`, HTTP Last-Modified и sitemap lastmod не используются.

SewItNow: в Next listing дат нет, но публичный GraphQL, используемый самим сайтом
(`https://api.sewitnow.ru/`), отдаёт `getProducts.list.created_at`. Это дата создания
товарной позиции у источника, соответствующая согласованному критерию «загружены
ими», а не гарантия времени первого публичного релиза. `updated_at` не используется.
Анонимные read-only запросы: `identSeller(domain)` и страницы `getProducts` по 100
позиций, шесть страниц на текущем каталоге. Сопоставление по публичному SKU из
канонического URL: parent ID из Next может отличаться. Первичные ID в нашей БД
не меняются. Из 535 позиций API 534 соответствуют выкройкам, одна игрушка исключена
существующим listing parser. На 28.10.2026 девять дат попадают в окно 60 дней.
Отдельное безопасное обновление дат: `python -m app.publications sewitnow`.
Команда не меняет availability и не запускает reconciliation; даты также загружаются
при обычном полном импорте. Повторные/ошибочные страницы не порождают новых дат.

На исследованных страницах VikiSews/Grasser/HelperSew публикационные даты не найдены.
Проверены Product JSON-LD, embedded JSON, клиентские скрипты и публичные каналы данных.
Публичные Bitrix RSS для товарных инфоблоков Grasser (6) и HelperSew (52) возвращают
пустой RSS. Sitemap содержит дату изменения, а не публикации. У VikiSews API требует
авторизацию; она не обходилась. Даты публикаций блога/Telegram не приравниваются
автоматически к дате загрузки выкройки. Для этих трёх брендов покрытие дат пока
не подтверждено; товары доступны в общем каталоге. Метка NEW не подменяет период.

Mini App показывает покрытие дат. Товары без даты остаются в обычном каталоге,
но не считаются доказанными новинками. Сортировка «Сначала новинки» поднимает
публикации последних 60 дней (свежие выше), остальные товары идут по названию.
Так неполное покрытие дат не группирует все старые модели одного бренда перед остальными.

## Бесплатные и за 1 ₽

Общая SQL-политика включает `is_free=1` либо цену ровно 1 RUB. Это работает для
всех источников и сочетаний аудитории/категории. Валютная единица USD не равна 1 ₽.
Пустая цена не считается бесплатной. Сам Product.is_free сохраняет смысл
бесплатного товара: позиция за 1 ₽ имеет False, цена показывается как 1 ₽,
а не «Бесплатно». Административный `Free` считает настоящие бесплатные отдельно;
CLI дополнительно показывает размер расширенного раздела.
