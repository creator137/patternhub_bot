# Фотографии: схема хранения и восстановления

## Подтверждённые причины

«Берет Рика»: старый URL в `sellty-assets-prod.storage.yandexcloud.net` возвращал
404, а текущая страница SewItNow отдавала тот же файл через
`api.sewitnow.ru/storage/image/...`. Полный импорт обновляет ссылку. Обогащение
детальной страницы нашло семь фото. Превью первой фотографии: 5590 байт,
увеличенная версия: 17574 байта в проверенном snapshot.

В выборке 12 фотографий на источник файлы Studio Yusupova достигали 1,4 МБ.
VikiSews Object Storage возвращает настоящий WebP как `application/octet-stream`;
этот тип разрешён с обязательным декодированием перед публикацией как `image/webp`.
У 32 товаров Grasser вместо обложки были выбраны SVG-иконки скидки/популярности/
мастер-класса внутри image container. Parser выбирает фотографии слайда и исключает
служебные template assets; worker обновляет метаданные после ошибки декодирования.
Один запрос Grasser закончился connect timeout. Это разные классы проблем:
изменившаяся ссылка требует обновления метаданных, временный сетевой сбой — повтора.

## Общая модель

`ParsedProduct.image_urls` / `Product.image_urls`: упорядоченная галерея без дублей.
`image_url` сохранён для совместимости. SQLite мигрируется аддитивно.
Listing без полной галереи не стирает уже полученный массив при upsert.
SewItNow и Studio Yusupova отдают галереи массово через существующие JSON parsers;
для остальных providers их собственные detail parsers обогащают фотографии в фоне.
В Telegram/web handlers нет импорта конкретных providers и открытия detail pages.

Метаданные фотографий не требуют хранения тяжёлых оригиналов на VPS.
В карточке загружаются обложка и ближайшие видимые миниатюры, остальные — при
просмотре. Один скачанный файл одновременно создаёт WebP 384 и 1280 пикселей.
Поворот EXIF учитывается; исходники после обработки не хранятся.

## Очередь и отказы

`media_assets`: URL, стабильный SHA-256 ключ, статус, попытки, следующий запуск,
последняя ошибка, время успеха/использования, приоритет и lease на скачивание.
SQLite lease предотвращает параллельное скачивание одного URL разными процессами.
Файл публикуется атомарным rename только после проверки и успешного сжатия.
`media_gallery_jobs` хранит отложенные ошибки обогащения; `product_media_cache`
связывает товар с последней успешно подготовленной обложкой.

- После каждого импорта новые/изменившиеся обложки регистрируются в общей очереди.
- До трёх быстрых попыток для timeout, connect/read errors, HTTP 408/429/5xx.
- Экспоненциальная пауза с jitter; учитывается `Retry-After`, включая HTTP-date.
- Затем ошибка остаётся в SQLite: фоновые повторы продолжаются с паузой до шести
  часов (либо дольше по явному Retry-After), а не исчезают после одного тайм-аута.
- Для 404/403 не повторяется немедленно тот же запрос: worker обновляет галерею
  товара и заменяет устаревший URL. Старый исправленный адрес выводится из очереди.
- Неудачное обновление не удаляет рабочий файл. Во время подготовки нового файла
  API может отдать последнюю рабочую обложку этого товара.
- Web запрос ждёт холодную подготовку максимум две секунды, затем возвращает
  Retry-After; задача продолжает работу в фоне. Компонент фото повторяет запросы,
  пробует оригинал и повторно проверяет восстановление позже, пока страница открыта.
- Одновременно скачиваются/обрабатываются не более двух фото на процесс; фоновые
  сервисы защищены flock. Основной каталог не ждёт обработки всех фотографий.

## Диск

`MEDIA_CACHE_MAX_MB=768` по умолчанию; также оставляется минимум 512 МБ свободно.
Очистка сначала удаляет редко используемые большие версии/второстепенные файлы,
затем старые обложки, если требуется. Изображения, удалённые из-за бюджета,
не прогреваются заново бесконечным циклом: они восстанавливаются при запросе.
При массовой обработке бюджет проверяется каждые 100 задач и в конце прохода;
это ограниченный кэш, а не архив всех оригиналов. Лимит мягкий между проверками.

Ориентир: 3500 обложек по 20 КБ занимают около 70 МБ; это оценка, фактический
объём зависит от изображений. При десятках тысяч товаров кэш остаётся ограниченным,
редко просматриваемые фото вытесняются. Удаление VPS требует восстановления БД,
но медиа можно построить заново из сохранённых URL и галерей.

Сами фото проверяются по реальному декодированию, ограничению байтов/пикселей.
Сервис принимает только ID существующего публичного товара, не произвольный URL.
Разрешены доверенные CDN-хосты, публичные DNS-адреса и проверенные редиректы.
Для нового provider дополнительные CDN добавляются через `MEDIA_ALLOWED_HOSTS`;
UI и алгоритм кэширования переписывать не нужно.

## Актуальность и планировщики

`allsewpattern-media.timer`: обработка очереди каждые пять минут после завершения
предыдущего прохода, по 250 задач. `allsewpattern-galleries.timer`: по 50 галерей,
новые товары первыми; источники чередуются, чтобы один медленный сайт не занял
всю очередь. Успешные галереи повторно проверяются не чаще раза в сутки.
Готовые файлы с неизменным URL можно перепроверить через 30 дней; старая копия
сохраняется при сбое. Изменившийся URL создаёт новую версию сразу.

```bash
python -m app.media --mode covers --limit 24
python -m app.media --mode register
python -m app.media --mode queue --limit 250
python -m app.media --mode galleries --product-id 2961
systemctl status allsewpattern-media.timer allsewpattern-galleries.timer
journalctl -u allsewpattern-media.service -n 50 --no-pager
```

Нельзя гарантировать отсутствие сетевых сбоев у чужих сайтов. Проверяемое
требование: ошибка не считается отсутствием фото; она сохраняется, повторяется,
видна в статистике очереди и не ломает уже скачанные изображения.

## Основания

- [Scrapy Media Pipelines](https://docs.scrapy.org/en/latest/topics/media-pipeline.html):
  переиспользование медиа, очередь одинаковых URL, хранение, thumbnail processing.
- [Scrapy RetryMiddleware](https://docs.scrapy.org/en/master/topics/downloader-middleware.html#retrymiddleware):
  отдельная обработка временных ошибок, повторные попытки и их приоритет.
- [AWS: limit retries](https://docs.aws.amazon.com/wellarchitected/2022-03-31/framework/rel_mitigate_interaction_failure_limit_retries.html):
  bounded retries, exponential backoff, jitter и проверка сценариев отказов.
- [MDN HTTP caching](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching):
  ETag, HTTP 304 и раздельная политика кэширования статических и динамических данных.

Применены эти принципы к существующему httpx/SQLite pipeline; перенос проекта
на Scrapy, Redis или отдельный платный CDN для текущего объёма не требуется.
