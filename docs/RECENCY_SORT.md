# От новых моделей к старым

Уточнение клиентки 28.10.2026: после выбора бренда, изделия и материала нужна
сортировка **всей** подборки от новых моделей к старым. Это не фильтр по возрасту
до 60 дней. Параметр `sort=new_first` теперь использует сохранённый порядок
производителя; число совпадений и остальные фильтры не меняются.

| Источник | Основание порядка |
|---|---|
| Grasser | Полный каталог `SORT=SORT&ORDER_BY=DESC`, выбранная сортировка «Новизне» проверяется в HTML каждой страницы; query сохраняется при пагинации |
| HelperSew | Собственная сортировка сайта «Новые выкройки»: числовой ID по убыванию, не строковое сравнение |
| VikiSews | Полный порядок основного каталога: в начале сейчас семь моделей «Новой коллекции», затем предыдущие. Это порядок сайта, не выдуманная дата и не время нашего импорта |
| Studio Yusupova | Подтверждённая дата публикации WordPress по убыванию, включая старые модели |
| SewItNow | Дата добавления позиции в публичном Sellty API по убыванию, включая старые модели |

Grasser/HelperSew/VikiSews не раскрывают точных дат. У VikiSews нет отдельного
публичного переключателя сортировки: используется текущий порядок каталога.
Производитель может менять его вручную. Ранг не доказывает календарный возраст
и не превращает модель в «опубликованную за 60 дней».

## Общая цепочка

Provider возвращает общий `RecencySnapshot(source, keys, basis, complete)`.
ProductRepository атомарно записывает `source_recency_rank` (0 — первая модель)
и `source_recency_basis`. SQLite migration аддитивная, с индексом `(source,rank)`.
У Product есть эти общие поля; source-specific условий в web/Telegram нет.

Ранги нельзя сравнивать как календарные даты разных брендов. В объединённом
каталоге сначала идут первые позиции брендов, затем следующие; при равенстве —
подтверждённая новизна, source, name, id. При выбранном бренде сохраняется его
порядок после любых фильтров. Стабильный id завершает сортировку и пагинацию.
Строки без ранга идут в конце, подтверждённые свежие даты помогают fallback.

## Обновление и защита

Успешный complete import обновляет порядок автоматически. Grasser/VikiSews
используют уже пройденный основной каталог, повторный обход при синхронизации
не запускается. HelperSew и датированные источники не требуют дополнительных
HTTP-запросов для вычисления ранга.

Отдельный запуск без изменения товаров/availability:

```bash
python -m app.recency helpersew studio_yusupova sewitnow grasser vikisews
```

Для повторного обхода VikiSews команда использует один последовательный client,
ссылки пагинации самого сайта и минимальный интервал 1 s. Принудительное увеличение
page_size при проверке давало timeout, поэтому не используется; основной импорт
сохраняет свои настройки.
Ошибки страницы, повтор страницы, лимит пагинации и неправильная сортировка
Grasser делают snapshot неполным. Пустой/incomplete snapshot не меняет старый
порядок. Дополнительно repository отклоняет snapshot с покрытием менее 90%
текущих available товаров. Замена рангов и отметка snapshot идут одной
транзакцией; upsert и detail enrichment ранги не стирают.

## Интерфейс

Сортировка по умолчанию — «От новых к старым». Сохранённый выбор пользователя
учитывается. Переключатель виден прямо под поиском на мобильном экране и также
доступен в панели фильтров. Фильтр `is_new` отдельно назван «За последние 60 дней» и сохраняет
строгое правило по датам. Так сортировка не скрывает старые модели, а возрастной
фильтр не выдаёт метку NEW за дату.
