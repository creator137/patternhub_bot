# Подписка allsewpattern

## Принятое решение

ЮKassa, redirect checkout по аналогии с `tarot-mini-app`. Пользователь подтвердил **ручное продление на 30 дней**, без автосписаний. Карты не сохраняем, `save_payment_method` не передаём. Отдельного кошелька нет.

7 дней предоставляются один раз на Telegram ID, по кнопке «Попробовать 7 дней бесплатно». Переустановка приложения, повторный `/start`, перезапуск сервера и отключение тарифа не сбрасывают trial. Покупка без активации trial означает отказ от trial. Покупка во время trial или действующей подписки добавляет 30 дней к оставшемуся времени. Смена цены не изменяет созданные заказы и оплаченные периоды.

ЮKassa выбрана заказчиком. Это не независимое подтверждение исключения из правил Telegram: официальные правила требуют Stars для цифровых услуг внутри ботов/Mini Apps. Внешний checkout сам по себе не устраняет этот риск. Перед публичным запуском владелец должен подтвердить применимость согласования к продаже доступа к каталогу. Провайдер самостоятельно не заменён.

## Интерфейс

- Кнопка «Подписка» (значок профиля) в шапке Mini App доступна всегда.
- При включённой монетизации в каталоге есть строка срока доступа.
- В разделе подписки: услуга, цена в рублях за 30 дней, trial, условия, кнопка оплаты, поддержка, история и проверка платежей.
- После истечения доступа каталог, карточки и список поставщиков блокируются сервером; раздел подписки и поддержка доступны. Избранное не удаляется.
- В боте: `/subscription`, `/terms`, `/support`, `/paysupport`. Legacy-каталог также проверяет доступ. Администраторы обходят ограничение.
- В админке: вкладка «Подписка», цена в рублях, HTTPS-ссылки на условия и поддержку, включение платного доступа. Использованы существующие PrimeVue-компоненты.
- Подписка на агрегатор не продаёт файлы выкроек: они приобретаются на сайтах производителей.

## Подготовка и запуск

1. Сделать резервную копию SQLite (включая согласованный WAL-снимок), обновить backend и собрать frontend. Перезапустить web и bot вместе. Новые таблицы создаются автоматически, существующий каталог не изменяется. По умолчанию подписка отключена.
2. В `.env` именно этого проекта задать `BOT_USERNAME`, `MINIAPP_URL` (HTTPS), `YOOKASSA_MODE=test`, тестовые `YOOKASSA_SHOP_ID_TEST`, `YOOKASSA_SECRET_KEY_TEST`, `PAYMENTS_ENABLED=true`. Не копировать секреты tarot-проекта.
3. В тестовом магазине настроить `https://<домен>/api/webhooks/yookassa` для `payment.succeeded`, `payment.canceled`, `refund.succeeded`.
4. В админке установить цену, реальные условия и контакт поддержки. Включение подписки заблокировано, пока магазин не настроен. Включать сначала только на тестовом окружении/отдельной БД.
5. Проверить в Telegram iOS/Android: новый пользователь → trial; завершившийся trial → checkout; отмену; оплату; возврат в бот; повторное открытие; повторное уведомление; возврат денег. Снимки для регистрации делать из реального Telegram, без имитации банковской оплаты. Цена должна быть утверждена владельцем, а не выдумана разработчиком.
6. Рабочий запуск: отдельные `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_MODE=live` и `YOOKASSA_LIVE_APPROVED=true`. Последний флаг устанавливается только после одобрения запуска, проверки условий продавца, поддержки, фискализации и правил платформы. Тестовые оплаты не предоставляют доступ в live; для тестирования использовать отдельную БД, поскольку trial привязан к тому же Telegram ID.

**Фискализация:** в этой версии `receipt` не передаётся, email покупателя не собирается. Требуется согласованная внешняя схема формирования чеков/освобождения продавца от этой обязанности. Если выбран чек средствами ЮKassa, перед live нужны отдельная настройка налогообложения и сбор контакта покупателя. Флаг LIVE_APPROVED не заменяет эту работу и не является юридическим подтверждением.

## Надёжность

Суммы — целые копейки. Цена и условия фиксируются сервером. POST заказа требует подтверждения текущей цены и условий. Повтор в течение часа возвращает незавершённый заказ; тайм-аут провайдера не меняет его Idempotence-Key. Спустя 23 часа создание потерянного заказа не повторяется: требуется ручная сверка, чтобы не выйти за окно идемпотентности провайдера. Старые заказы с известным provider ID можно проверять всегда.

Webhook не принимается за доказательство оплаты: выполняется авторизованный GET платежа, сверяются ID, metadata, сумма, RUB, режим test/live и `paid`. Только `succeeded` открывает доступ. Транзакция SQLite и уникальный provider ID защищают от повторного зачисления. Возврат с checkout лишь открывает `/start subscription`, но не изменяет доступ.

Фоновая сверка web-процесса каждые 30 секунд обрабатывает до 100 ожидающих заказов, включая потерянный ответ создания. История в Mini App позволяет повторить сверку вручную. После успешной оплаты автоматическое повторное создание исключено. Неполученный refund webhook можно восстановить ручной проверкой платежа; администратору следует контролировать возвраты в кабинете ЮKassa.

Возврат выполняется в кабинете ЮKassa; webhook или проверка отзывают соответствующий период доступа. Частичный возврат также отзывает весь 30-дневный период: пропорциональные возвраты этой версией не поддерживаются. Это необходимо согласовать в условиях до запуска.

Картинки и агрегированная статистика каталога остаются публичными; список товаров, детали, ссылки продавцов и поставщики защищены. Уже доставленные пользователю сообщения/данные технически не отзываются.

## Проверки

`python -X utf8 -m unittest discover -s tests`

`npm.cmd --prefix frontend run build`

Браузерный тест `frontend/e2e/subscription.spec.ts` использует mock API, не проводит платежи. Он проверяет мобильный экран, согласие, trial и отображение цены. Это не проверка реального магазина ЮKassa.

Источники: [формат API](https://yookassa.ru/developers/using-api/interaction-format), [уведомления](https://yookassa.ru/developers/using-api/webhooks), [правила Telegram](https://core.telegram.org/bots/payments-stars).
